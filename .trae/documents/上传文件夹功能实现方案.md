# 上传文件夹功能 实现方案

## Context（为什么做）

当前「我的文件」只能通过 `#fileInput`（`type="file" multiple`，`dashboard.php` L276）选择**单个文件**，
或把零散文件拖到 `#dropZone`。用户想要**直接上传整个文件夹并保留目录结构**。

好消息是底层能力已具备：
- 上传接口 `api/upload.php` 的 `start`/`finish` 已接收并落库 `folder_id`（L770、L865/L903、L1128、L1220）；
- 文件夹创建接口 `api/folder.php` 的 `action=create`（L40-L49）已可用，且有 `normalizeFolderName()`（L14-L22）可复用；
- 页面 `body` 已带 `data-folder`（当前所在文件夹 id，`dashboard.php` L138）。

因此本功能主要是**前端补「选目录/拖目录 → 递归取文件 → 按相对路径建好文件夹 → 逐个文件落到对应文件夹」**，
外加一处**必须的后端修正**（见下）。

## 关键决策（已与用户确认）

1. **同名文件夹**：弹出对话框让用户选择「合并进已有」或「新建一个」（不能静默决定）。
2. **同时支持拖拽文件夹**（不只按钮）。
3. **文件重名检查改为「按文件夹隔离」**（现为全盘范围）。

## 为什么必须改重名逻辑

`findActiveUploadByName()`（`src/helpers.php` L1002-L1014）与 `nextAvailableFilename()`（L1017-L1036）
只按 `user_id` 查重，**不带 folder 条件**。文件夹上传时不同子目录常含同名文件（如 `a/readme.txt`、`b/readme.txt`），
按现有逻辑它们会互相判定为重复；用户若选「覆盖并上传」（`duplicate_action=overwrite`），
`$resolveDuplicate()`（`api/upload.php` L158-L177）会把**另一个子目录里的同名文件**当作旧文件释放/覆盖 —— 会误删数据。
故必须把查重与自动编号限定在**同一文件夹内**。

## 实现步骤

### 一、后端：重名检查按文件夹隔离

1. `src/helpers.php`
   - `findActiveUploadByName(int $userId, string $name, int $folderId = 0)`：SQL 增加 `AND folder_id <=> :folder_id`
     （NULL 安全等值，根目录用 NULL 匹配，与 `dashboard.php` L111 的 `folder_id <=> :folder_id` 写法一致）。
   - `nextAvailableFilename(int $userId, string $name, int $folderId = 0)`：透传给上面的查重。
2. `api/upload.php`
   - `$resolveDuplicate` 闭包（L159）增加第 3 个参数 `int $folderId`，传给上面两个函数。
   - 三处调用点补传 `folderId`：L422（`commitDirectUpload()` 已有同名形参 `$folderId`）、L1199（`$folderId` 已在 L1128 算好）、
     **L1111 需把 L1126-L1132 的 `$folderId` 解析块上移到 L1111 之前**再传。
   - `mode=check`（L627-L640）：改为接受 `items`（JSON 数组 `[{name, folder_id}, ...]`）；若未传 `items` 则回退旧的
     `names` + 单个 `folder_id`，避免旧缓存前端报错。逐项按各自 folder 查重。

### 二、后端：一次请求建好整棵目录树

`api/folder.php` 新增 `action=create_tree`（放在 `action=create` 之后），用于避免「一个文件夹一个请求」：

- 入参：`parent_id`（当前所在文件夹）、`paths`（JSON 数组，相对路径，如 `["A","A/B","A/B/C"]`）、
  可选 `inspect=1`（只探测不创建）、可选 `merges`（JSON 数组，命中的路径选择「合并进已有」）。
- 判重复用现有文件夹表：按 `user_id` + `parent_id <=> ?` + `name = ?` 查子文件夹（MySQL 排序规则天然大小写不敏感，
  与现有 `action=create` 语义一致），命中即复用其 id。
- `inspect=1`：只返回 `conflicts`（已存在、需要用户选择的路径数组），不写库。
- 正常调用：按路径顺序（父先于子）逐段解析，命中且在 `merges` 中则复用、否则 `INSERT` 新建；
  返回 `folders`（`{ "A": 12, "A/B": 13 }`）。路径段一律经 `normalizeFolderName()` 校验。
- 套用与 `action=create` 相同的既有约束：登录校验（`Auth::requireLogin(true)`）、封禁拦截（`userActiveBan`）、
  CSRF（`Security::verifyCsrf`）、`parent_id` 归属校验（`folderRow`）。

> 这样前端无需解析 `#folderOptions`，也无需给 `dashboard.php` L359 加 `data-parent-id`，后端是唯一权威。

### 三、前端：选目录 / 拖目录

`dashboard.php` 上传区（L275-L279）新增一个隐藏 input 与按钮：

```html
<input id="folderInput" type="file" webkitdirectory directory multiple hidden>
<button type="button" id="browseFolderButton">选择文件夹</button>
```

`assets/app.js`：

- 新增 `#folderInput` 与 `#browseFolderButton` 的取值，加入 L69 的「已存在性」探测数组（保持与其他元素同风格）。
- 目录选择：`folderInput.addEventListener('change', () => addFolderFiles([...folderInput.files]))`。
- **拖拽目录**：`drop` 处（L1292）改为优先读 `event.dataTransfer.items`，用 `item.webkitGetAsEntry()`
  递归读取（`FileSystemDirectoryEntry.createReader().readEntries()`，需循环读取直到返回空数组）；
  拿不到 `items`/`getAsEntry` 时回退现有 `addFiles(event.dataTransfer.files)`；
  递归结果里同时包含散落文件与目录内文件（`entry.isFile` / `entry.isDirectory`）。
  为区分「散落文件」与「目录内文件」，给每个文件附上相对目录路径（对散落文件为空串）。

### 四、前端：同名文件夹冲突弹窗

仿 `confirmOverwrite`（L993-L1018）新增 `askFolderConflict(name)`：复用同一套 `<dialog class="duplicate-dialog">`
骨架与样式，但返回**动作字符串**而非布尔：

- 按钮 `data-choice="merge"`（合并进已有）/ `data-choice="new"`（新建一个）；
- Esc / `cancel` 视为 `merge`（与 `confirmOverwrite` 把 Esc 当「自动编号」的安全默认一致）；
- resolve `'merge' | 'new'`。

### 五、前端：入队与上传改造

- **entry 扩展**（L1032）：`{ file, item, duplicateAction, folderId, relPath }`。
- **`upload()`**（L1076）解构增加 `folderId`、`relPath`；
  `startFields`（L1092）把写死的 `folder_id: document.body.dataset.folder` 改为
  `folder_id: folderId ?? (document.body.dataset.folder || '0')`（散落文件仍落当前目录）。
- **`runQueue()` 串行、`pendingWrite` 轮询等保持不变**（不改并发模型，避免引入配额竞态）。
- **新增 `addFolderFiles(files)`**：
  1. 由每个文件的 `webkitRelativePath` 取相对目录路径，汇总出目录路径集合（含各级父路径，父先于子排序）；
  2. `POST api/folder.php action=create_tree&inspect=1` 取 `conflicts`；
  3. 对每个冲突路径依次 `askFolderConflict()`，把选 `merge` 的收进 `merges`；
  4. `POST action=create_tree`（带 `merges`）拿到 `folders` 路径→id 映射；
  5. 逐个文件按 `validate()` 校验、建队列条目（`.queue-meta b` 显示**相对路径**，便于区分同名文件）、
     入队 `{ file, item, duplicateAction: '', folderId: folders[dirPath], relPath }`；
  6. 重名检查：把 `[{name, folder_id}]` 一次性发给 `mode=check`（改后的 `items` 契约）；
     命中即弹**现有的** `confirmOverwrite()`（此时已是同文件夹内重名，覆盖是安全的）；
     对目标为**本次新建**的文件夹（`inspect` 未列为冲突）可跳过检查以省请求。
  7. 选中文件数过多时先给一次确认（例如 >200 个），避免误选整个磁盘后串行传很久。
- **`previewRename`**：文件夹场景不再用它预测编号（DOM 里没有子目录的行），
  命中重名时状态文案写「等待上传（同名将自动编号）」，真实名字由服务端返回后在 L1130-L1134 已会自动更新。
- **累计配额**（针对批量场景的小改进）：`remaining`（L936）由 `const` 改 `let`，
  每次上传成功后按 `file.size` 递减（服务端判定为 `overwrite` 时不递减），使后续 `validate()` 能提前拦下「剩余空间不足」，
  而不是传到最后一个才失败。

### 六、样式与版本号

- `assets/app.css`：为队列条目新增一个用于「相对路径」副标题的小类（如 `.queue-path`），
  或在 `.queue-meta` 里为路径行补样式；`.queue-meta small` 现在只显示大小，需并存路径信息。
- 因改动静态资源，按项目约定**全站同步版本号**：`assets/app.js?v=35 → ?v=36`（10 页）、
  `assets/app.css?v=62 → ?v=63`（引用页数量实施时以 grep 为准）。实施后需 grep 确认无旧版本号残留。

## 验证方案

1. **静态检查**：`php -l` 全部改动 PHP 文件；`node --check assets/app.js`。
2. **本地 DB 只读验证**（遵守「禁止还原/清库」红线，只做 SELECT / 事务内回滚）：
   - 验证 folder 隔离后的 `findActiveUploadByName()`：同名文件在 `folder_id=NULL` 与 `folder_id=X` 下互不命中。
   - 验证 `action=create_tree` 的 `inspect` 与创建结果（路径→id 正确、父先于子、重名复用）。
3. **HTTP 冒烟**：本地内建服务器登录后确认 `dashboard.php` 200、新按钮渲染、`app.js?v=36` 与 `app.css?v=63` 均 200。
4. **生产部署与实测**（按既定「GitHub + FTP 双写」流程）：上传后清 OPcache，
   用一个测试文件夹（含嵌套子目录 + 不同子目录同名文件）实测：
   - 目录结构正确还原；
   - 不同子目录同名文件**各自独立存在**、不再互相重名；
   - 同名文件夹弹窗出现且「合并 / 新建」两条路径都符合预期；
   - 拖拽文件夹与按钮两种入口均可。
5. 生产验证后删除所有临时探针文件并 grep 确认无残留。

## 已知限制（会在交付说明中告知用户）

- 浏览器 API 限制：**空文件夹无法识别**（`webkitRelativePath` 只随文件出现），空目录不会被创建。
- 上传仍为**串行**（沿用现有 `runQueue`），文件夹文件很多时耗时较长。
- 文件夹冲突弹窗按路径逐个出现；若冲突较多会有多次弹窗（与现有文件重名弹窗的交互一致）。
